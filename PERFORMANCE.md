# Open-form performance recording

Enable only in a test session using `?sags_perf=1` (or `window.__SAGS_FORM_PERF__ = true` before scripts load). Open a roster form normally, then read `window.sagsFormPerformance.results()` and export its JSON. Nothing is sent to a server and no form values/account IDs are recorded. Default recording is off. The module is called directly inside canonical receive/open functions; it does not monkey-patch or add another business wrapper.

Recorded marks: form-open-start, form-session-ready, form-local-data-ready, form-server-data-ready, form-render-start, form-first-visible, form-interactive. Trace-specific marks prevent overlap between opens. Start correlates the captured task click (where available); a programmatic open starts at handler entry. Session includes assignment resolution. The measured localStorage span is the seed/envelope block. Data hydration includes handover/upstream business logic and mixed local/Firebase I/O, so it is NOT claimed to be pure network duration. Rendering is switchFlightSession. First-visible is a two-animation-frame paint opportunity, not a screenshot assertion; interactive is the existing syncFormActions callback completed after that paint checkpoint. Validate both against the browser trace.

IndexedDB, Firebase transport, and image readiness are explicitly marked unmeasured rather than zero. Capture a DevTools Performance/network trace alongside the JSON to separate those, plus actual CPU/business work and LCP/INP/CLS. FINAL and UNIT_TASK use separate renderers; their full timing is not yet instrumented. No performance improvement claim is made without traces.

Collect cold/warm opens on mobile/desktop, network/throttling/device conditions, form type, run count and cache state. Keep the baseline source commit and report click-to-first-visible and click-to-interactive distributions, not a single best run. Do not optimize/consolidate unrelated UI before trace review. This instrumentation does not certify role workflows, keyboard/phone PWA behavior, or server timings.
