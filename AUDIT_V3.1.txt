BUG CONFIRMED
- Permission editor stored featureOverridesV485 with Firestore set(...,{merge:true}).
- featureOverridesV485 is a nested map. When a later save omitted an old override key (for example revoking a previously granted permission or RESET TO ROLE DEFAULT), merge semantics could preserve old nested keys.
- Result: UI could report saved while an older override remained effective.

FIX
1. Permission save now uses DocumentReference.update() with featureOverridesV485 as one complete field, replacing the whole override map.
2. After write, app immediately reads the same Firestore document back.
3. Saved map and permissionRevV485 must exactly match the requested values before success is shown.
4. RTDB account_permissions revision signal remains event-based (no heartbeat) for online clients.
5. Personal-session verification now repaints role/form UI when only permission overrides/revision changed.
6. Permission realtime listener is restarted on pageshow/session restoration.
7. Service Worker cache/build bumped to V3.1 and new permission-authority-v31.js is precached/fresh-networked.
