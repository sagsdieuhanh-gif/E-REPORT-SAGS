## Chưa thể kích hoạt chỉ bằng thay đổi repository/GitHub Pages
1. **Firebase retention 24h**: GitHub Actions `.github/workflows/flight-retention-48h.yml` đang thất bại ở bước xác thực. Cấu hình `vars.FIREBASE_WIF_PROVIDER` kèm Workload Identity/service account `sags-retention@e-report-sags.iam.gserviceaccount.com`, hoặc `secrets.FIREBASE_SERVICE_ACCOUNT_JSON` (tài khoản dịch vụ có quyền tối thiểu, quản lý ngoài mã nguồn). Kiểm tra dry-run trước; chỉ bật apply sau khi AD kiểm tra phạm vi xóa và lưu bản sao. Không lưu JSON khóa vào repository.
2. **Supabase standby**: workflow `.github/workflows/supabase-standby-mirror.yml` bị bỏ qua theo chủ đích nếu `vars.SAGS_STANDBY_REPLICATION_ACTIVE` không là `true`. Trước khi bật cần `secrets.SAGS_STANDBY_SUPABASE_SERVICE_ROLE_KEY`, Firebase backup-reader WIF `SAGS_STANDBY_FIREBASE_WIF_PROVIDER` + `SAGS_STANDBY_FIREBASE_SA_EMAIL` hoặc `SAGS_STANDBY_FIREBASE_SERVICE_ACCOUNT_JSON`, thử dry-run và kiểm tra khôi phục trên môi trường cách ly.
3. **Firestore Rules production**: cần quyền truy cập Firebase để xác thực bản đang chạy trước khi siết `sags_handovers`; không sửa trực tiếp quyền chung vì có các loại hồ sơ đang dùng chung collection. Chạy emulator với các trường hợp DH, CBTT, KH, PVHK, AD trước khi đưa lên server.
4. **Firebase Admin reset**: nguồn Cloud Function `firebase/functions/index.js` hiện không định nghĩa `adminResetAuthPassword`. Nút reset trên web sẽ báo lỗi an toàn nếu backend không tồn tại; không tuyên bố đã reset Firebase thành công. Cần triển khai backend riêng được xác thực và cấp quyền AD nếu dùng reset bằng mật khẩu một lần.
