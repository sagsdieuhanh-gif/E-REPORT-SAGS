# E-REPORT SAGS V2.0

Build: `V2.0-20261006-SETTINGS-HOME-FIX-01`

## Corrections

- Home Settings buttons previously clicked the theme switch, or selected dark mode. Both home entry points now open the Settings Center through the native menu, with a direct opener fallback.
- Settings remains available in the mobile system menu, including when it is the only available system item.
- Successful settings opens no longer schedule a forced reopen 180 milliseconds later. Closing the window stays closed.
- Runtime version badges use the release metadata rather than older fixed version strings.
- Settings styles are scoped to the Settings Center so generic `.grid`, `.actions`, `.rows` and related selectors cannot change other forms.
- Menu observation shares one animation frame and does not reconnect to the same menu on every identity refresh.

## Build consistency

Several reviewed My Flight fixes existed in generated phase files but were missing from the legacy monolith. Their current implementations are now retained as canonical inputs in `app/core/phases/`. Edit these inputs for phase changes; `npm run build:runtime` copies them to their executable outputs and rebuilds runtime chunks, boot groups, styles and integrity metadata. The original monolith remains as legacy reference.

## Validation

- 45 regression tests pass, including a new home Settings routing test.
- All application and build JavaScript parses successfully.
- All 185 manifest assets match their declared byte counts and SHA-256 hashes.
- Browser checks used a local simulated CO profile: desktop home Settings, mobile home Settings at 390 × 844, appearance tab navigation, close and reopen, and release version display.
- Existing test doubles were updated for the current policy configuration, combined FSAGS 208 completion/send workflow, and My Flight label. Administrator carrier settings and production permissions were not changed.

Authenticated Firebase operations, device notification permission prompts, and physical iOS/Android PWA installation require a real account/device and were not exercised by the local browser check. Passing these checks does not establish that every possible production workflow is error-free.

## Use

The archive contains the complete project. Serve its root through an HTTPS static host; do not open `index.html` with `file://`. For future changes, install the locked development dependencies, run `npm run build:runtime`, then `npm test` before publishing. A new cache build separates this release from older PWA shells. If an installed device retains the previous shell, open `repair.html` on the same deployed origin.


## Production deployment

Vercel hosting configuration remains unchanged. GitHub Pages links redirect to https://e-report-sags.vercel.app/ while keeping query and hash. The production host contract is covered by a regression test.
